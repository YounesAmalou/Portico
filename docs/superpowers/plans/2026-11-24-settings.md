# Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a preferences file (`~/.config/portico/settings.toml`), `portico settings [set] [--json]`, a TUI settings overlay on `,` that hides tabs and runs the desktop integration's install and uninstall, and teach the desktop panel to hide the same tabs.

**Architecture:** `platform::paths` gives the location. `domain::settings` reads the file and writes one key at a time with `toml_edit`, keeping comments. `App` carries the path and exposes `settings()` and `set_setting()` to both interfaces. The TUI filters `Tab::ALL` through the settings. The overlay starts `portico desktop install|uninstall` as a child process while the TUI is suspended. The panel reads `settings --json`.

**Tech Stack:** Rust, `toml_edit`, clap, ratatui, Quickshell/QML.

**Spec:** `docs/superpowers/specs/2026-11-24-settings-design.md`

## Global Constraints

- File: `$XDG_CONFIG_HOME/portico/settings.toml` when `XDG_CONFIG_HOME` is absolute, otherwise `~/.config/portico/settings.toml`. Only `main` reads the environment.
- Keys: `tabs.tunnels`, `tabs.docker`, `tabs.podman`, `tabs.proxmox`. All are booleans, default `true`, and the hosts tab is always on.
- The CLI ignores the settings. Only `portico settings` reads the file. `containers`, `shell`, `tunnels` and `tunnel` behave as today.
- Every write is under the `platform::fs` lock, atomic (`write_unique` + `rename_to` + `sync_dir`), with mode `0644`. Writing over an invalid file is refused.
- Unknown keys are ignored on reading and kept on writing.
- Tests must never touch the developer's real config: every test command removes `XDG_CONFIG_HOME` or points it into the temporary home.
- No new dependency other than `toml_edit`. It must pass `cargo deny` and the MSRV in `Cargo.toml`. Pick the newest `toml_edit` that builds on that MSRV.
- Commits follow Conventional Commits and carry no AI attribution, no `Co-Authored-By` trailer.
- `scripts/ci-checks.sh` must pass, run as a regular user.

## Review Focus

1. **A file that is valid TOML with the wrong shape** (`tabs = true`, `[tabs] podman = "no"`): it must be reported as invalid with its line. It must not panic and must not silently become the defaults. Test in Task 1.
2. **Turning off the tab that is open, or every container backend**: the TUI must land on Hosts, and `c`, `T` and the digit keys must not reach a hidden tab. Test in Task 6.
3. **An unwritable config directory, or a file that became invalid while the overlay is open**: the toggle must show the error and keep its old value, with no crash. Test in Task 7.
4. **The `portico` executable missing or failing when an overlay action runs**: the TUI must come back and report it. Test in Task 7.
5. **The panel with a `settings --json` error document, or an older Portico without `settings`**: the panel must keep every feature. Test in Task 8.

  - `pub fn set(path: &Path, key: Key, value: bool) -> Result<bool, SettingsError>`. It returns whether the file changed. It is a no-op returning `false` when the value is already in effect, whether written or by default.
