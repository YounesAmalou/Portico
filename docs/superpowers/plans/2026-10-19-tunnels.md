# Tunnels Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Saved tunnels (one local, remote or dynamic TCP forward through a known host) that are listed, added, edited and removed from the CLI and a TUI tunnels screen, and started and stopped on demand as ordinary `ssh -f` processes that Portico finds again from a runtime record, verified so a recycled PID is never signalled.

**Architecture:** `src/tunnel.rs` is the pure model (validation, OpenSSH spec syntax, the tunnels file, collisions, status types, ssh arguments). `src/tunnel/store.rs` is the file transaction (lock, strict re-read, validate, atomic replace with `tunnels.bak`). `src/tunnel/runtime.rs` owns the runtime directory, records, `/proc` identity checks against an injectable `/proc` root, the background-process scan and rediscovery, bind tests, and the start and stop mechanics. `src/app/tunnels.rs` composes them with the inventory and `ssh -G` into `TunnelReport`s and the operations. The CLI adds `tunnels` and `tunnel …`; the TUI adds a `Mode::Tunnels` whose state, keys, form, start worker and rendering live in `src/tui/tunnels.rs`.

**Tech Stack:** Rust 2024, clap derive, ratatui 0.30, crossterm 0.29, libc, fs2. No new crates.

**Spec:** `docs/superpowers/specs/2026-10-19-tunnels-design.md`

## Global Constraints

- No new dependencies; no daemon; nothing starts or restarts automatically.
- Every ssh argument is passed directly; no shell. The start command line is exactly the spec's (`-f -N -o ExitOnForwardFailure=yes -o BatchMode=yes -o ControlMaster=no -o ControlPath=none -o RemoteCommand=none -E <log> <-L|-R|-D> <spec> -- <alias>`).
- A process is signalled only through a pidfd opened before the identity check passed.
- `TunnelStatus` names are `stopped`, `running`, `failed`, `port-in-use`; `TunnelReport` and `TunnelStatus` hold only printable, credential-free data with stable field names.
- Runtime directory: `$XDG_RUNTIME_DIR/portico/tunnels/` when it is an absolute path to a directory owned by the user, else `~/.ssh/portico/run/tunnels/`; directories `0700`, files `0600`.
- `src/openssh.rs` changes only by making `open_pidfd` and `signal_pidfd` `pub(crate)`. The hosts screen changes only by the `T` key, the mode dispatch and the footer entry.
- Before each commit run `scripts/ci-checks.sh fmt`, `clippy` and `test` as a regular user; run `e2e` and `docs` in the last task.
- Conventional Commits; no AI attribution anywhere.

## Review Focus

- **A recycled PID** (same PID, other start time, other boot, other UID, zombie, or a command line without the log path) is never treated as the tunnel and never signalled. Pinned in Task 2 (`identity_rejects_*`) and the e2e `stop_never_signals_a_stranger`.
- **A lost record** (runtime directory cleared, crash before the record write) is rebuilt from `/proc` and the tunnel stays stoppable. Pinned in Task 2 (`rediscovers_a_tunnel_without_a_record`) and the e2e `a_deleted_record_is_rediscovered`.
- **Concurrent starts of colliding tunnels** cannot both pass the conflict check: `start.lock` is held from the check to the record write. Pinned in Task 4.
- **The default bind address** tests both `127.0.0.1` and `::1`. Pinned in Task 1 (`listen_addresses_*`).
- **`T` versus `t`** on the hosts screen: `T` opens tunnels with or without Shift reported, `t` still tests. Pinned in Task 6.

### Task 1: The model (`src/tunnel.rs`)

**Files:** create `src/tunnel.rs`; modify `src/lib.rs`.

**Produces:**
- `Kind { Local, Remote, Dynamic }` with `flag()` (`-L`/`-R`/`-D`), `directive()` (`LocalForward`/…), `name()` (`local`/`remote`/`dynamic`).
- `Forward { kind, bind_address: Option<String>, bind_port: u16, target: Option<(String, u16)> }` with `parse(kind, spec)`, `spec()` (OpenSSH command-line syntax), `directive_value()` (the file's two-word form), `describe()` (`127.0.0.1:5432 → localhost:5432`, `socks 1080`, `remote 8080 → localhost:3000`), `listen_addresses()` (local and dynamic only: default → `127.0.0.1` and `::1`; `*`/empty → `0.0.0.0` and `::`; otherwise the address as given).
- `Tunnel { name, host, forward }` with `new` validating name and host.
- `TunnelsFile { tunnels }` with `parse(&str) -> Result<_, TunnelFileError>` (strict, line numbers), `render()`, `find`, `insert`, `replace`, `remove`.
- `collisions(&[Tunnel], &Tunnel) -> Vec<String>` (names of saved tunnels that collide).
- `TunnelStatus { Stopped, Running { pid, started }, Failed { reason, finished }, PortInUse { address, by } }` with `name()`; `TunnelWarning { UnknownHost(String), CollidesWith(String) }`; `TunnelReport { tunnel, status, warnings }`.
- `start_args(log: &Path, tunnel: &Tunnel) -> Vec<OsString>`.

- [ ] Write the unit tests listed in the spec's Testing section for `src/tunnel.rs` (spec parsing per kind, IPv6 brackets, `*`, rejected forms, file round trip and errors, collisions, `listen_addresses`, `start_args`).
- [ ] Implement until they pass; commit `feat: model saved tunnels and their file`.
