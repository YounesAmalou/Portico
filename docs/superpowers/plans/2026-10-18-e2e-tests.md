# End-to-End Tests Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An opt-in test target `tests/e2e.rs` that runs the real `portico` binary in a pseudo-terminal against a real unprivileged `sshd`, run locally with `scripts/ci-checks.sh e2e` and in CI as a new `e2e` job.

**Architecture:** Three test-crate modules. `sshd.rs` starts a throwaway server, `client.rs` builds an isolated home with an `ssh` wrapper that keeps OpenSSH out of the real `~/.ssh`, and `terminal.rs` drives a pseudo-terminal through `portable-pty` and reads the screen with `vt100`. Every test is `#[ignore]`d, so the normal `test` job only compiles it.

**Tech Stack:** Rust 2024 (MSRV 1.88), `portable-pty` 0.9, `vt100` 0.17, OpenSSH (`/usr/bin/sshd`, `/usr/bin/ssh`, `/usr/bin/ssh-keygen`), GitHub Actions in `archlinux:base-devel`.

**Spec:** `docs/superpowers/specs/2026-10-18-e2e-tests-design.md`

## Global Constraints

- No product code changes (`src/` untouched).
- Dev-dependencies only: `portable-pty = "0.9"`, `vt100 = "0.17"` (checked: both build on 1.88 and pass the existing `deny.toml`).
- Every e2e test carries `#[ignore = "end-to-end: run with scripts/ci-checks.sh e2e"]`.
- A missing `/usr/bin/sshd` fails the test with a message saying to install OpenSSH's server. It never skips.
- Server: `127.0.0.1`, random port, all files in a temp dir, `StrictModes no`, `UsePAM no`, `LogLevel ERROR`, `ForceCommand` banner script. It is killed on drop, and a failed listen is retried up to 3 times with a new port.
- Banner script output: `portico-e2e ready` then, after reading one line, `portico-e2e got <line>`.
- Client: hosts use absolute `IdentityFile` paths, the wrapper's isolation options live in a final `Host *` block of the flattened config, and the wrapper passes through unchanged when Portico supplies `-F`.
- Every test asserts that the real `~/.ssh/known_hosts` (from the password database) is byte-for-byte unchanged.
- Terminal: 120×24, a default wait deadline of 10 s, and timeouts fail with the screen dump. crossterm's `ESC[?u ESC[c` query is answered with `ESC[?62;c` only.
- Tests run as a regular user, `scripts/ci-checks.sh` must pass, and commits follow Conventional Commits with no AI attribution.
- Do not edit `ROADMAP.md`.

## Review Focus

1. Tests running in parallel threads, each with its own `sshd`: ports must not collide, and the retry has to handle a lost race. Task 1 adds a test that starts 8 servers concurrently.
2. A loaded CI runner: no fixed `sleep`s anywhere, only polling waits with deadlines. Reviewers reject any `thread::sleep` used as synchronization (polling loops may sleep a few ms between checks).
3. A developer whose login shell is fish or zsh with a noisy rc: interactive sessions must never reach it. Task 2's connect test asserts that the banner is the first remote output after the host-key prompt.
4. A failed assertion mid-test must not leak `sshd` or `portico` processes: `Drop` kills both. Task 2 checks that dropping a `Terminal` whose child still runs reaps it.
5. A user config that already sets `UserKnownHostsFile` per host: per-host values win over the wrapper's `Host *` default. Task 1's moved `portico test` checks rely on the default only, and Task 3's host-key-changed test writes nothing per host.

Readiness means polling a TCP connect every 20 ms for up to 10 s. If the child exits before listening, retry with a new port, up to 3 attempts, then panic with sshd's stderr (pipe stderr to a file in the temp dir).

- [x] **Step 5: Implement `client.rs`.** The wrapper `ssh` (POSIX sh) works like this:
  - It scans the arguments for `-F`. If one is present, it runs `exec /usr/bin/ssh "$@"`.

    ```
    Host *
      UserKnownHostsFile <home>/.ssh/known_hosts
      GlobalKnownHostsFile /dev/null
      IdentityAgent none
      IdentitiesOnly yes
    ```
    then runs `exec /usr/bin/ssh -F "$HOME/.ssh/e2e-flat-config" "$@"`.

  The wrapper `ssh-keygen` runs `exec /usr/bin/ssh-keygen "$@"`. Write both with `tests/support/executable.rs`'s `write_executable` (include it through `#[path]`). `Client::new` asserts that its home is not the real home.
